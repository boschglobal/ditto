# Attempt 1 — interleaved order (superseded, kept for the order-effect comparison)

These files are the first production-config baseline (2026-09-30, 16:17–16:44 UTC), generated by the pre-review
version of the harness. The baseline one level up (`../`) supersedes them. They are kept only because the T15a
hand-offs cite them to show how much the run order moved the numbers.

How attempt 1 differs from the baseline in `../`:

- **Order.**
  - Attempt 1 ran round → shape: round 1 of every shape, then round 2 of every shape, then round 3.
  - Each shape's timed iterations therefore started right after a different shape had run, and a bind's pages were
    often evicted by the shapes in between.
  - Example: shape 5 always ran directly after the five shape-4 variants, and shape 1 directly after shape 5, which
    uses the same city cycle.
  - The baseline runs each shape's 3 rounds back to back.
- **Plans.**
  - The `EXPLAIN (ANALYZE, BUFFERS, SETTINGS)` outputs here ran with parallel workers where the plan had a `Gather`
    (shape 2).
  - The shipped `findAll` never gets those workers: its fetch size makes PostgreSQL execute the portal with a row
    limit, which runs parallel plans leader-only.
  - The iteration-0 plans were also captured after the cross-check executions of the same statement, so they are
    hotter than the timed iterations.
  - Do not read these plans as the shipped execution.
- **Catalog check.** `load.md` and `environment.md` here used the earlier, name-based catalog check. The baseline
  compares against a reference built from the production DDL.
- **Cold numbers.** Taken with the same cold protocol as the baseline. They are re-measured in `../cold.md`.

The per-round `-> n=20` lines of attempt 1 are in the untracked session log
`docs/tmp/deck-verify-2026-09-28/results/logs/T15a-warm-1m-2.log`. All numbers quoted from attempt 1 in the
hand-offs come from these committed files.
