## Service cursor (keyset) vs OFFSET pages

The service cursor ("keyset") page and the `limit(offset,25)` page at the same position are not the same request: the cursor's resume filter is an ordinary criteria and gets the per-field read auth of the sort path, the OFFSET page only the `global_read` restriction (sort keys carry no auth, plan §3.3 exception 3; Mongo shares the cursor code), so they can differ. Behind a `null` anchor (inside the block of things without the sort path) the filter's `nor(exists(sortPath))` branch is true for missing AND for non-readable values, so non-readable things stay in; behind a populated anchor only readable things follow. "root-readable" = the subject pair is in the root `·g` and not in the root `·r` of `policy_auth` — for `/features/env/properties/temperature` the only level this corpus grants on.

- `4-keyset`: 25 rows, 0 root-readable; `4-offset`: 25 rows, 0 root-readable; rows in both pages: 25.
